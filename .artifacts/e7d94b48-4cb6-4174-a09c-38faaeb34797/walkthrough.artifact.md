# Walkthrough - Roles & TargetRoles Schema Standardization

I have completed the full standardization of the database schema and codebase terminology. This resolves all TypeScript compilation errors and ensures a consistent naming convention throughout the application.

## Core Changes

### 1. Database Schema Evolution
Standardized the naming of membership arrays to avoid confusion with internal system types:
- **User Model**: Renamed `memberTypes` to **`roles`**.
- **Event Model**: Renamed `targetMemberTypes` to **`targetRoles`**.
- **Prisma Client**: Regenerated the client to reflect these changes across all modules.

### 2. Codebase Refactoring
Updated over 20 files to use the new standardized properties. This includes:
- **Attendance Systems**: All Abalat and Mezmur attendance sheets now correctly filter by user `roles`.
- **Event Management**: The event creation and update flows now use `targetRoles` to define which members should attend.
- **Member Dashboards**: Updated all student and member detail pages to display and check the new `roles` field.
- **Reporting & Eligibility**: Fixed the eligibility service to accurately check multi-role memberships using the new schema.

### 3. Data Migration Success
I have updated and re-executed the **Member ID Migration Script** (`src/scripts/migrate-member-ids.ts`).
- **Standardized IDs**: All members now have IDs in the strict `FH-XXXX-YY` or `FHC-XXXX-YY` format.
- **Role Recovery**: Successfully restored user roles into the new `roles` array based on their registration history.
- **Year Derivation**: Automatically extracted Ethiopian registration years from account creation dates to populate the `YY` part of the IDs.

### 4. Build Stability
- **Type Safety**: Verified that `npx tsc --noEmit` now passes with **zero errors**.
- **Isolation**: Confirmed that Course-only students remain hidden from Abalat/Mezmur lists until they are officially recommended and registered.

## How to use
- **Admin Actions**: When creating an event, the "Target Roles" selection now accurately reflects the new schema.
- **Member Access**: Members should continue to use the 6-digit (4 random + 2 year) codes generated by the system.
- **Recommendations**: The "Send File" workflow remains active, allowing Course students to gain the `REGULAR_MEMBER` role and receive their additional `FH-` ID.

> [!IMPORTANT]
> The database columns have been renamed. If you use custom SQL queries outside of this app, please update `roles` (formerly `memberTypes`) and `targetRoles` (formerly `targetMemberTypes`).
>
> If you encounter a `PrismaClientKnownRequestError` mentioning the old column names, please restart your development server to ensure the Next.js cache is fully refreshed with the new schema.

> [!TIP]
> The automatic cursor jump on the login page is now fully type-safe and active for all users.
